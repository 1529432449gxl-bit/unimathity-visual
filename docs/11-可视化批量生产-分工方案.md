# 可视化批量生产分工方案

本方案适用于全站可视化模块的批量制作。现有三款 AI：Claude、GPT、Grok。实测 Claude 的可视化效果最好，GPT 与 Grok 一般。方案的出发点是把最强的能力用在最难的环节，其余环节交给另外两家，同时用模板和自动预检降低每个模块的成本。制作规范以 07 号调优提示词与 08 号制作要求表为准。

## 一、可视化由 Claude 直接制作

原因：过去的流程是其他 AI 先实现、Claude 再调优。初稿质量一般，调优时常常整体重写，一个模块付出两份工作量。认可的样板大多是一次做成的。

做法：新模块由 Claude 从头制作。GPT 与 Grok 在交付之后各做一次复核，专门寻找数学错误和显示问题。

预期效果：单个模块的耗时和来回次数减少，质量稳定在样板水准。

## 二、建立分类模板库

原因：08 号要求表把内容分成 16 类，同一类模块的骨架基本一致。每次从零写，耗时耗额度，风格也容易走样。

做法：每类选一个认可的样板整理成模板，项目现有的共用组件（plotfx、morph、steady、mathviz-kit）一并纳入。新模块在模板上替换数学内容即可。模板库从线性变换类起步，参照 8.1 特征值几何意义演示与正交矩阵演示。

预期效果：同类模块越做越快，消耗越来越少，全站风格统一。

## 三、按类别成批制作

原因：按章节推进时，曲线、矩阵、概率等类型交替出现，每次切换都要重新适应规范。

做法：先列出全站需要可视化的小节，按 08 号要求表归类，一次完成一整类。

预期效果：同批模块质量一致，模板在第一个模块上打磨好，后续模块直接受益。

## 四、选题交给 GPT 与 Grok

原因：判断哪些小节值得做可视化，主要靠通读讲义、对照学生痛点，对作图能力要求不高。

做法：由 GPT 或 Grok 通读讲义，按 08 号要求表的分类标出候选小节，每条附一句理由。经人工挑选后交给 Claude 制作。

预期效果：Claude 的额度集中用于作图，做什么、不做什么始终由人工掌控。

## 五、自动预检与集中审阅

原因：逐个打开检查很累，很多问题机器就能发现，例如曲线冲出画面、手机宽度下溢出、报错、动画停住不动。

做法：每个模块交付前，先在电脑宽度和手机宽度下自动截图检查。一批模块汇总到一个审阅页，在一页内看完，逐个标记通过或重做。

预期效果：送审的都是能正常运行的版本，人工只需判断好不好看、对不对。

## 六、每批的标准节奏

1. GPT 或 Grok 选题，列出候选小节与理由。
2. 人工挑选本批要做的模块。
3. Claude 基于模板集中制作，并完成自动预检。
4. GPT 与 Grok 复核数学与显示。
5. 人工在审阅页验收，通过的模块接入讲义。

额度紧张时优先做曲线类模块，这一类目前最不满意，提升也最明显。

## 硬性规则：n 阶一般情形

所有演示动画、可视化与交互模块一律以 n 阶一般情况为例（元素写成 $a_{ij}$、$b_i$ 等一般记号，用省略号表示中间行列），不用具体的二阶、三阶、四阶情况或具体数字矩阵代替。
