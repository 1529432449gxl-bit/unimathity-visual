本文供新开的云端会话接手 Unimathity 可视化工作时先读。新会话读不到 Unimathity 项目的专属记忆，下面把必须知道的约定和当前进度写全。读完后按"当前任务"一节继续。

网站名 Unimathity，后台为 Django + Vue，工作副本在 D:\MathAPP。讲义知识库在 content\library\knowledge\<课程代码>\，课程代码有 calculus、linear-algebra、probability、complex-analysis、real-analysis、ode、abstract-algebra、numerical-analysis、number-theory。课程原始资料在 D:\Math_APP_course，每门课一个英文名文件夹。docs 下文件名为"编号-中文名-用途"格式。可视化相关规范：07 号调优提示词、08 号制作要求表、11 号批量生产分工方案。选题清单与筛选结果放在 D:\MathAPP\review。

站长另有计划：云端只写代码，产物交回本地编译运行，云端工作区可放在他 GitHub 账号 1529432449gxl-bit 下的仓库 unimathity-visual。若本会话已关联他的电脑并能直接读写 D:\MathAPP，按他当时的指示选用其中一种方式。

## 合作方式

跟站长讨论方案时只讲原因、解决方案、预期效果，不讲技术细节。改动网站内容前的关键步骤先经他确认。可视化由 Claude 从头制作，GPT 与 Grok 负责选题和复核。

## 可视化硬性要求

画面上尽量不出现文字、小字描述和数据读数，确需标注时只用极少量英文或公式，解释留在讲义正文。不展示不稳定、退化、失败的情形。逐步演示一律带自动播放与暂停。涉及矩阵或符号阵列的讲解与演示一律用 $n$ 阶一般情形，不用二阶、三阶、四阶具体例子代替。复杂的符号推导不做动画，参照数值分析 6.2 雅可比与高斯-赛德尔的做法画一张 TikZ 静态图。站长对曲线类模块普遍不满，常见毛病是曲线生硬、算例函数太平滑导致迭代一两步就挤在一起。认可的水准样板为首页六格动画、数值分析 1.1 三个应用场景、5.2 消元演示、6.2 迭代系数拆分演示、8.1 特征值几何意义演示、微积分 5.1 定积分定义演示。

## 筛选标准

沿用线性代数那次的三分法。动起来才讲得清的做动画或交互；步骤多、静态图能讲清的改做 TikZ 推导图；正文能讲清、偏冷门、过于抽象、只有展示失败情形才有意义的取消。同一张画面换位置讲的条目合并成一个模块、配多种模式，跨课程可共用。依附例题的旧模块不重写，直接下线或改静态图。筛选后的文件格式参照 review\线性代数-可交互建议-gpt.md：开头写统计与筛选标准，再分"动画与交互模块""TikZ 推导图""取消"三节，原稿另存为"筛选前备份"。
