### 一、先看样板，对齐水准

动手前先打开并操作以下站长认可的样板，体会它们的共同点，以此为标准：

- 首页六格动画：frontend\src\utils\heroScenes.js
- 数值分析 1.1 三个应用场景：frontend\src\utils\showcaseScenes.js
- 数值分析 5.2 消元逐步演示：interactive\matrix-steps.html
- 数值分析 6.2 系数矩阵三色拆分（TikZ 静态图）与雅可比逐步演示：interactive\jacobi-steps.html
- 数值分析 8.1 特征值几何意义：interactive\eigen-geometry.html
- 微积分 5.1 定积分定义：frontend\src\components\interactive\RiemannSum.vue
- 曲线类的参照实现：interactive\newton-method.html、fixed-point-case.html

样板的共同点就是验收标准：

1. 动起来但克制。状态变化一律有过渡：曲线连续变形，新元素逐段画出或淡入，点弹出，历史轨迹按年龄淡出。任何地方都不允许“整张图瞬间重画”。
2. 算例要能看出东西。函数要有足够的弯曲，迭代要有足够的步数在画面里展开；如果几步就挤到一起，首选第三节的“逐步放大细节”，其次换函数、换初值。只展示方法正常工作的样子；确属讲义内容的反例要有清楚的对照。
3. 画面干净。不放标题、说明文字和数据堆砌；必要的文字用英文，公式、图例、标签一律 KaTeX。不画卡片边框、背景网格和密集刻度，坐标轴只留细线和少量刻度。
4. 线条细腻。圆头圆角（lineJoin/lineCap = round），按像素宽度自适应采样，主曲线 2.4px，次要线 1–2px，用透明度区分层次，不靠加粗。
5. 界面稳定。逐步演示播放时，控件、公式区、画面的位置都不许跳动：页面加载时预排所有步骤，锁定各区最大高度；滑块等预排不到的情况用“只增不减”兜底。
6. 操作统一。逐步演示带 ↺ ◀ 计数 ▶ Play/Pause，手动操作即暂停，键盘左右键可用，离开视口或切到后台自动暂停。只能点着走的模块一律加自动播放。

### 二、统一视觉规格

浅灰底 #fbfbfa，主色深蓝 #223056，第二色橙 #ad6844，浅蓝 #3f6e8c 作第三色，灰 #7a7c84 作辅助线。逐步演示中更新项用橙框 #b5763a 配浅橙底 #f3e3d2，引用项用深蓝框配浅蓝灰底 #eeeff4。按钮为深蓝描边、播放中才填充。字体“Microsoft YaHei”，正文 14px。讲义引导句里的颜色统一叫深蓝、橙色、浅蓝、灰色，和画面一致。

### 三、经验：逐步放大细节（镜头跟随）

收敛类迭代（牛顿法、割线法、不动点、二分、幂法等）越往后步长越小，固定视窗里后几步必然挤成一点。做法是让镜头跟着当前这一步走：每一步把视窗缓动到恰好框住当前两点（如 $x_k$ 与 $x_{k+1}$）和曲线上相关的点，左右留约三到七成余量；放大后在角落放一张整体小图，画出整条曲线、已走过的点和当前镜头框，学生始终知道自己在哪。镜头移动要缓动，不能跳。这样每一步都看得清，放大倍数一步比一步大，本身就把收敛速度（如平方收敛）演示出来了。参照实现是 interactive\newton-method.html（plotfx.js 的 view().aim() 加小地图）。凡是迭代点会聚集的模块都优先考虑这个做法，再考虑换算例。

### 四、可用的共用件（在 interactive\vendor\ 下，优先复用，不要另造或内嵌副本）

- plotfx.js：曲线类模块的绘制与动效层。包含视窗与镜头缓动（view/aim）、逐段画出（path 的 progress）、点弹出（dot 的 scale）、TeX 标签层（labels）、逐步播放器（stepper，自带按钮和自动播放）、统一页面样式（style）。新写或重写曲线类页面时用它。
- morph.js：给“按参数重画”的旧页面补连续变形。把画线前的采样数组交给 Morph.v(key, 数组)，参数变化时调用 Morph.bind(draw) 返回的 kick()。
- steady.js：消除逐步演示的抖动。Steady.sweep 预排步骤锁定高度，Steady.hold 只增不减。
- mathviz-kit.js：组件库，已是统一样式；逐步页在初始化末尾调用 MV.stabilize(fig, 步数, i => player.seek(i), () => player.seek(0))。

### 五、做法

1. 逐个打开目标页面，在浏览器里实际操作一遍（拖滑块、单步、播放），对照第一节六条列出差距，再动手。
2. 小问题就地修；结构太差的页面直接用 plotfx.js 重写，保留原来的数学内容和接口（url 参数、iframe 高度回报 runge-height）。
3. 换算例时用 Python 实算迭代序列，确认每一步在画面里分得开、不出界。
4. 改了画面就同步改讲义里对应的引导句（颜色、操作方式、算例函数），其余正文不动。
5. 改前把原文件复制到 D:\MathAPP\_to_delete\<日期>-<说明>\，不永久删除。

### 六、自检

- 每个页面截图检查静止画面，并在参数改变后约 0.1 秒再截一张，确认是过渡中的画面而不是跳变。
- 逐步页从头点到尾，记录控件条位置和页面高度，必须始终不变。
- 浏览器控制台无报错；手机宽度（约 380px）下不溢出、不重叠。
- public 与 dist 两处文件一致（核对 md5）。

## 硬性规则：n 阶一般情形

所有演示动画、可视化与交互模块一律以 n 阶一般情况为例（元素写成 $a_{ij}$、$b_i$ 等一般记号，用省略号表示中间行列），不用具体的二阶、三阶、四阶情况或具体数字矩阵代替。
